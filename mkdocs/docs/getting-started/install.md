# Install (Linux & Windows)

First-time setup on a site PC: clone the `fps` branch, build the Docker image, and confirm the stack is running.

---

## Prerequisites

- Ubuntu 22.04 or 24.04 LTS (bare-metal, not WSL) **or** Windows 10 build 19041+ / Windows 11
- Internet access for the initial install (pulls Docker images and Python packages)
- `sudo` rights (Linux) or admin rights (Windows)
- No Python, CUDA, or PyTorch needed on the host — everything runs inside Docker

!!! warning "WSL2 is not supported for production"
    WSL2 adds UDP tail latency and complicates static-IP lock-down. Use native Ubuntu on site PCs.

---

## Linux install

### Step 1 — Clone the fps branch

```bash
git clone --branch fps https://github.com/waledroid/IsiDetector.git ~/fps
cd ~/fps
```

If `git` is not yet installed:

```bash
sudo apt install -y git
```

Alternatively, run the one-liner bootstrapper (installs `git`, clones, and prompts to run `run_start.sh`):

```bash
curl -fsSL https://raw.githubusercontent.com/waledroid/IsiDetector/fps/install.sh | bash
```

### Step 2 — Run `run_start.sh`

```bash
./run_start.sh
```

This is a one-time bootstrap. It:

1. Detects whether an NVIDIA GPU is present
2. Installs Docker Engine (if missing)
3. Installs NVIDIA Container Toolkit — GPU hosts only
4. Verifies GPU access inside Docker
5. Fixes Docker DNS if Ubuntu's `systemd-resolved` stub would break the build
6. Builds the Docker image
7. Writes `deploy/.deployment.env` with the detected mode (`gpu` or `cpu`)

| Mode | Base image | Inference backends | Build time |
|---|---|---|---|
| CPU (no GPU found) | `python:3.11-slim` (~1.2 GB) | OpenVINO `.xml`, ONNX CPU | 2–4 min |
| GPU (NVIDIA detected) | `nvidia/cuda:12.8` (~5 GB) | ONNX-CUDA, TensorRT, YOLO `.pt`, RF-DETR `.pth` | 5–15 min |

To override auto-detection:

```bash
./run_start.sh --force-cpu   # build CPU image even on a GPU host
./run_start.sh --force-gpu   # build CUDA image even with no GPU visible
```

!!! note "Log out after the first install"
    `run_start.sh` adds your user to the `docker` group. That membership only takes effect after you log out and back in (or run `newgrp docker` in the current shell).

### Step 3 — Copy model weights

The repo does not ship trained weights. Copy them from the office workstation via `scp`:

```bash
# CPU site PC — use OpenVINO for best performance
scp -r isidet/models/yolo/<date>/openvino \
    user@<site-ip>:~/fps/isidet/models/yolo/<date>/

# GPU site PC — ONNX is portable; .engine files must be built per-host
scp isidet/models/yolo/<date>/weights/best.onnx \
    user@<site-ip>:~/fps/isidet/models/yolo/<date>/weights/
```

!!! tip "CPU hosts — use OpenVINO"
    `.xml` + `.bin` (OpenVINO IR) gives 1.4–2× the throughput of ONNX-CPU on Intel hardware.

!!! warning "RF-DETR + OpenVINO is rejected at load time"
    OpenVINO 2026 mistranslates transformer Einsum ops. Use `.onnx` or native `.pth` for RF-DETR.

### Step 4 — Start the stack

```bash
cd ~/fps
./up.sh
```

The browser opens at **http://localhost:9501** when the stack is ready. For daily start and stop commands, see [Daily start / stop](../daily-ops/start-stop.md).

## Windows install (CPU only)

1. Clone the `fps` branch:

    ```cmd
    git clone --branch fps https://github.com/waledroid/IsiDetector.git C:\logistic
    ```

2. Double-click **`Install.bat`** at the repo root and accept the UAC prompt.

    The installer silently:
    - Checks Windows 10 build 19041+ / Windows 11
    - Downloads and installs Docker Desktop with the WSL2 backend (~5–10 min)
    - Caps the hidden WSL2 VM at 4 GB RAM / 2 vCPU / 2 GB swap (written to `%USERPROFILE%\.wslconfig`)
    - Builds the CPU Docker image
    - Creates an **IsiDetector** desktop shortcut

3. If the installer ends with "log out and back in", do so — Docker Desktop adds your account to `docker-users` and group membership refreshes only at next sign-in.

To start the stack after install, double-click the **IsiDetector** shortcut or run `Start.bat` at the repo root.

## The `.deployment.env` marker

`run_start.sh` writes `deploy/.deployment.env` at the end of a successful build:

```
# Auto-generated by run_start.sh — do not edit.
COMPOSE_MODE=cpu          # or: gpu
SUDO_DOCKER=              # empty if user is in docker group; "sudo" otherwise
```

`./up.sh` reads this file every run to pick the correct Compose overlay without re-detecting hardware. If the marker is missing or says `gpu` but `nvidia-smi` is unreachable, `up.sh` falls back to CPU mode automatically with a warning.

To regenerate the marker (e.g. after swapping hardware), re-run `./run_start.sh`.

## Update flow

Pull new code and restart the stack — Docker rebuilds only changed layers:

```bash
cd ~/fps
git pull
./up.sh
```

On Windows (PowerShell at the repo root):

```powershell
git pull; .\Start.bat
```

Pulls that touch only configs or docs restart in seconds. A pull that changes `deploy/requirements-deploy.txt` or the `Dockerfile` triggers a full layer rebuild (2–10 min depending on mode).
